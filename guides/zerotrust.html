🔒 Zero Trust & SASE Architecture

Modern perimeter-less security design for cloud-first, hybrid, and remote-work environments.

The End of the Perimeter

Traditional security architectures assumed a hard perimeter: everything inside the network was trusted, everything outside was untrusted. Cloud adoption, remote work, and sophisticated lateral-movement attacks made this model obsolete. Zero Trust replaces perimeter trust with continuous verification — "never trust, always verify."

Zero Trust — Core Tenets (NIST SP 800-207)

NIST defines Zero Trust as a set of guiding principles, not a specific product or technology. The seven tenets are:

  1. All data sources and computing services are resources. The network is not trusted — devices, users, and services must all authenticate regardless of location.
  2. All communication is secured regardless of network location. No implicit trust based on being "inside" the corporate network.
  3. Access to individual enterprise resources is granted on a per-session basis. Each request is evaluated; access to one resource doesn't imply access to others.
  4. Access to resources is determined by dynamic policy. Policy evaluates identity, device health, behavior, and context — not just credentials.
  5. All enterprise-owned and -associated devices are monitored and validated. Device posture is continuously assessed.
  6. All resource authentication and authorization is dynamic and strictly enforced. Reauthentication triggers on significant context changes.
  7. The enterprise collects information about the current state of assets, network infrastructure, and communications. Data drives continuous improvement of posture.

Common Misconception: Zero Trust is not a product you buy. It's an architectural philosophy implemented through multiple technologies: identity, device management, network segmentation, application access controls, and data protection — working together.

Cross-Cutting Capabilities

CISA also identifies three cross-pillar capabilities that enable ZT maturity:

  • Visibility & Analytics — continuous monitoring, UEBA, behavioral baselines
  • Automation & Orchestration — automated response, policy enforcement, SOAR integration
  • Governance — ZT strategy ownership, risk appetite, policy lifecycle management

Zero Trust Architecture Components

NIST SP 800-207 defines two key ZT components: the Policy Decision Point (PDP) and the Policy Enforcement Point (PEP). Every access decision flows through these.

  • Policy Engine (PE) — makes the trust decision based on policy rules and data from trust algorithm
  • Policy Administrator (PA) — establishes and shuts down communication paths between subject and resource
  • Policy Enforcement Point (PEP) — the gatekeeper; enables, monitors, and terminates connections based on PDP decisions

Supporting systems feed the Policy Engine:

  • Identity Provider (IdP) / Directory
  • Device Health / MDM / EDR signals
  • SIEM / threat intelligence feeds
  • Data access policies / DLP
  • Network flow / traffic analysis

Identity as the New Perimeter

In a ZT architecture, identity is the primary control plane. Key identity architecture concepts:

  • Strong MFA — phishing-resistant (FIDO2/passkeys) preferred over SMS/TOTP for privileged access
  • Conditional Access — grant access only when identity + device + context meet policy thresholds
  • Privileged Identity Management (PIM) — just-in-time elevation, no standing privilege
  • ABAC over RBAC — Attribute-Based Access Control enables fine-grained, context-aware decisions vs. coarse role assignments
  • Identity Governance — automated access reviews, orphaned account detection, separation of duties enforcement

Network Micro-Segmentation

Replacing the flat "trusted internal network" with segmented zones that limit lateral movement. Three primary approaches:

  • Network-based segmentation — VLANs, SDN, firewall rules between segments
  • Host-based segmentation — software-defined perimeters, host firewalls, workload isolation
  • Application-layer segmentation — service meshes (Istio/Envoy), API gateways with mutual TLS

SASE — Secure Access Service Edge

SASE (pronounced "sassy") is a Gartner-coined architecture that converges wide-area networking (WAN) with cloud-native security services. Instead of backhauling traffic to a datacenter for inspection, security is delivered from the cloud edge — closest to where users and workloads actually are.

ComponentFunction
SD-WANSoftware-defined WAN for intelligent traffic routing across branches, cloud, and internet
SWG (Secure Web Gateway)URL filtering, malware inspection, SSL inspection for internet-bound traffic

ZTNA (Zero Trust Network Access)Replaces VPN with identity-aware, application-specific remote access
FWaaS (Firewall as a Service)Cloud-delivered next-gen firewall for all traffic types

SSE vs. SASE

Security Service Edge (SSE) is the security-only subset of SASE (SWG + CASB + ZTNA), without the SD-WAN networking component. Many organizations adopt SSE first and add SD-WAN later. Vendors: Zscaler, Netskope, Palo Alto Prisma Access, Cloudflare One.

BeyondCorp — The Blueprint

Google's BeyondCorp (2014) is the most influential real-world ZT implementation. Key principles that translate to any enterprise:

  • Access should not be granted based on network location
  • Access is granted based on device and user credentials
  • All access to enterprise resources is authenticated, authorized, and encrypted
  • Every device has a certificate-based identity; posture is continuously assessed

ZT Implementation Roadmap

A practical sequence for most enterprise environments:

  1. Phase 1 — Identity Foundation: Deploy phishing-resistant MFA, implement Conditional Access, inventory all identities (human + service)
  2. Phase 2 — Device Visibility: MDM enrollment, EDR deployment, device compliance policies
  3. Phase 3 — Application Access: Replace VPN with ZTNA for critical apps, enforce app-level MFA
  4. Phase 4 — Network Segmentation: Define macro-segments, begin workload isolation for critical systems
  5. Phase 5 — Data Protection: Classify sensitive data, enforce DLP, encrypt data at rest and in transit across all tiers
  6. Phase 6 — Continuous Optimization: Behavioral analytics, automated response, ZT governance program

Role Prep: Be prepared to discuss how you would approach a ZT roadmap for a hybrid organization — what you'd prioritize first and why. Interviewers for security architecture roles frequently ask this as a practical design question. Identity first is almost always the right answer, because it provides the control plane for everything else.
